关于 Kestrel

红隼（kestrel）是种小猎禽，悬停很久才落下去一次。这个应用想要的是同一种耐心：笔记软件不必频繁打扰你，数据一直停在你自己的机器上。

定位

本地优先的桌面笔记应用，把「按时间记的日记」和「按主题写的文章」放进同一个屋顶下。中文界面，Windows 安装包，无账号、无网络依赖。

缘起

写日记的软件和写文章的软件往往是两台机器上的两回事：日记本按日期翻，文章按主题攒，中间那些「今天忽然想明白的一件事」两头都不收。Kestrel 的起点就是把它合成一件事——同一套 [[双链]] 笔记体，日记里的一段可以原地升格成文章，文章里也能指回某一天。组织方式（标签、属性、图谱、反链）为这两种形状共用，而不是各做一套。

技术栈

  • 外壳：Electron 44 + React 19 + TypeScript + Vite（electron-vite）。
  • 状态：Zustand 5；快捷键与命令面板读同一张注册表（src/renderer/src/commands.ts），不会出现「面板里有、键位没接」这种对不上的情况。
  • 数据库：Node 内置的 node:sqlite，所以零原生模块——不装 node-gyp，不会因为 Electron 换版本而重编译失败。
  • 编辑器：所见即所得是 Tiptap，源码模式是 CodeMirror 6，两边切换有无损判据。
  • 字体：Maple Mono（连同中文回退栈打包进安装包，运行期不下载任何东西）。
  • 打包：electron-builder + NSIS，按当前用户安装，中文安装界面；安装包未做代码签名。

依赖很少：除了上面这些，运行期只多用到 lowlight 与若干 Tiptap / CodeMirror 官方扩展包。

架构分层

  • src/main/ — Electron 主进程：SQLite 访问层、迁移、IPC、首次启动示例。
  • src/preload/ — 暴露给渲染进程的白名单接口。
  • src/renderer/ — React 界面：store（Zustand）/ 编辑器 / 组件 / 主题。
  • src/shared/ — 两个进程都用的纯函数：日期、链接与标签解析。

渲染进程不碰文件系统，一切读写走 IPC 到主进程；界面拿到的是白名单里的方法，不是 Node 能力。持久化集中在主进程的一个 SQLite 文件上，迁移和索引都在那一层做完。

路线图

  • v0.1.0（当前）：日记 + 文章 + 双链 + 标签 + 属性 + 回收站 / 历史版本这套安全网。
  • v0.2.x：想做图谱的力学布局与动效（现在的画法太僵硬）、外观细化。
  • v0.3：想做站内搜索；Ctrl+F 这个键位已经为它留白，Ctrl+Shift+F 被「专注模式」占着，所以搜索留给 Ctrl+F。
  • 更远的：.md 导入导出。

不做的事同样写清楚了：云同步、协作与多人编辑、插件系统、移动端，见非目标。
